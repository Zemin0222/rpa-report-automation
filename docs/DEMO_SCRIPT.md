## 一、3 分钟现场演示与讲解脚本（问题 → 方案 → 亮点 → 取舍）

### `[0:00 - 0:35]` 背景痛点与项目定位
> “传统企业运营与财务日常经常面临跨系统数据孤岛：每天早上要先登录 CRM 导出订单表、登广告后台翻页抓消耗、再从财务系统下载 PDF 结算单与本地/邮箱手工票据核对，最后出 Excel/Word 日报并人工填进 OA；员工报销也要人工逐张看电子发票、算限额、防重复后再填进报销系统。
> 针对这个痛点，我基于 **Playwright + FastAPI + Python** 做了一个可插件化扩展的 **跨系统 RPA 自动化工作台**，不仅全自动闭环跑批，还带实时浏览器操作直播视窗和 AI 辅助分析。”

### `[0:35 - 1:35]` 现场打开工作台展示双业务场景
1. **场景一：每日全渠道对账与 OA 日报（`daily_ops_report`）**
   - 展示「经营总览与对账」Tab：指出 5 张核心 KPI、渠道明细表的异常红标（ROI < 2.0 / 退款率飙升 / 日环比暴跌），以及展开的 **「根因诊断 ▾」抽屉**与**三方对账差异「归因清单 ▾」抽屉**，点明左侧标签（「规则兜底」/「缓存命中」/「AI 生成」）。
   - 切到「趋势与报表下载」：演示连续 7 天走势与动态生成的飞书/钉钉卡片预览及 4 Sheet 图表 Excel / 带图 Word 附件下载。
2. **场景二：发票智能识别与自动报销（`expense_reimburse`）**
   - 在左侧切换「自动化流程」为 **发票智能识别与自动报销**，点击 **「观看机器人实时操作」**。
   - 边看直播边解说：工作台高亮显示机器人登录报销后台、新增报销明细行、逐张填入类别/票号/销售方/金额、上传发票原件 PDF 并获取 `EXP-2026xxxx` 回执单号；回到总览页面点击第 4 张被拦截票据（餐饮 680 > 200），对照**右侧票面原件缩略图与风险原因标签**。

### `[1:35 - 2:25]` 工程化与技术亮点深挖
1. **可插拔场景引擎**：`core/runner.py` 托管锁、幂等、步骤审计、截图留痕与备份；业务只需实现 `Workflow` Protocol（`collect / process / deliver / kpi_view`）注册即可扩展新场景。
2. **可观测 + 可降级的 AI 网关**：`ai/gateway.py` 对接 OpenAI 兼容接口（可环境变量一键切 DeepSeek / 通义 / GPT），内置 SHA256 SQLite 语义缓存、单日次数/Token 预算熔断、Pydantic 输出校验加失败自修重试；无 Key 或超预算自动零感知退回确定性规则引擎。
3. **公网演示隔离与单工位队列**：`DEMO_MODE=1` 下支持访客免密体验 + IP 滑窗限流（`429`）+ 管理操作 `403` 只读锁；由于浏览器极其消耗内存，全站收口到 `SingleWorkerQueue` 串行排队，忙碌时用**历史成功录像先行回放**承接排队访客，不让页面干等。

### `[2:25 - 3:00]` 收尾与取舍总结
> “因为定位在 1~5 人内部团队与单机 2C4G 部署，我没有为了堆技术把 Postgres、Redis、Celery 和 K8s 全拉进来，而是用 SQLite WAL + 进程内单工位队列保持极简可运维；整套仓库配备 31 项自动化 `pytest` 测试和 GitHub Actions CI 自动验证，保证每轮改造可回归。”

## 二、面试官高频追问应对预案

1. **真实网站有滑块验证码、企业微信扫码登录怎么处理？**
   - 团队内置 `python main.py auth-login --site xxx --url ...` 启动有头浏览器让运维扫码/过验证后将 `storage_state` 持久化至 `storage/auth_states/`；后续无头容器直接注入复用。遇 Cookie 过期跑批失败时自动全页截图保存并推送红色告警卡片通知人工重新续期，遵循不强行绕过 CAPTCHA/反爬风控的合规边界。
2. **如果目标网站改版、前端 DOM 变了导致机器人挂了怎么办？**
   - 工作台「模拟故障截图」演示的就是这一场景：超时/异常立刻触发当前视口截图留痕、记录 `FAILED` 到 `step_logs` 并下发带定位信息的告警预览；支持多场景互不影响及单独 `--force` 重跑修复日。
3. **为什么不直接用 Redis + Celery 队列，而自己写内存 `SingleWorkerQueue`？**
   - 单机单副本 Docker 下进程内 `queue.Queue` + `threading` 零额外服务依赖、毫秒级获取 `ahead_count` 与 `estimated_wait_sec` 供前端直播页实时展示，且能在不部署 Broker 的情况下在 CI 与单测中以毫秒速度完成并发序列化验证；未来如果横向扩展成多 Worker 实例节点，只需把 `SingleWorkerQueue` 接口背后替换为 Redis List 即可平滑迁移。
4. **Linux 下做中文 PDF 发票解析踩过什么坑？**
   - PyMuPDF 配合 `NotoSansCJK` 生成并由 `pdfplumber` 提取中文时，很多常见汉字会被抽成 `U+F900~U+FAFF` 兼容区码位（如“金/辰”），正则直接失配；在抽取入口统一走 `unicodedata.normalize("NFKC", text)` 并为精简 CI 环境实现内置 CJK 字体回退后彻底解决跨平台差异。

## 三、可直接放入简历的项目描述（4 条精选）

- **跨系统 RPA 工作台架构设计与场景引擎重构**：设计基于 `Workflow` 协议的插件化执行引擎（`collect → process → deliver`）与通用调度运行时，实现 SQLite WAL 幂等状态库、30 分钟并发锁超时回收、步骤级耗时审计、故障自动截图告警及在线热备；将既有日对账流水线无损迁入并通过门面模式保持兼容，新增「发票智能识别与自动报销」场景端到端落地。
- **Playwright 浏览器自动化与实时操作直播体系**：封装可高亮标注页面元素的 `BrowserManager` 与 `LiveRunTracker`，支持 登录态复用（`storage_state`）、跨表翻页抓取、SPA 接口拦截、PDF 财务对账单与多行报销明细附件自动上传，并在 FastAPI SPA 控制台提供毫秒级关键帧直播与单步回放能力。
- **可观测 OpenAI 兼容网关与确定性规则双引擎**：封装统一 `AiGateway`，集成 SHA256 SQLite 语义缓存、单日调用与 Token 预算熔断、Pydantic 强校验自修复重试及规则引擎无缝兜底，覆盖发票抽取、渠道异常归因、对账差异核查与日报建议四大能力，并在前端透明呈现推理来源（AI / 缓存 / 规则）与预算遥测。
- **公网演示沙箱工程化与 CI/CD 部署**：构建 `DEMO_MODE` 访客守卫中间件与 `SingleWorkerQueue` 单工位串行队列，实现反代穿透 IP 滑窗限流（429）、管理写操作隔离（403）、排队期历史录像自动先行回放及每日凌晨数据重置，并基于 Caddy 自动 HTTPS 与 GitHub Actions CI（31 项 `pytest` 单测/集成测试 + Docker 镜像构建）完成标准化交付。
